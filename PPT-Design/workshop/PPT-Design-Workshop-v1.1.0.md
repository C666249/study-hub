# PPT 设计工坊｜项目共享规范

**版本：1.1.0 · 更新日期：2026-11-09 · 状态：核心规范已建立，素材与动画案例持续收录**

这份文件供同项目的其他会话、本机 Codex 与后续制作者读取。它规定设计、编辑、保护动画和收录方法。把本文件放入项目共享资料后，可以要求接手会话“先读取《PPT 设计工坊》，再按本次任务操作”。不要假设其他聊天会实时知道本次变更。

## 核心约定

**以可编辑的内容结构为基础，以统一色调、材质和排版秩序建立整体，以内容驱动的疏密变化形成呼吸感；对于用户已确认的效果图，同时以逐项视觉复刻作为交付硬标准。**

1. 重要文字、数字、年份、图表标注必须保持原生可编辑；图表数据和关系结构也应有可编辑来源。
2. 照片、纸纹、装饰与文字分层；需要动画的主体、阴影、背景与遮挡独立。整页图片不能冒充可编辑 PPT。
3. 同一套 PPT 的主色、字体层级、线条和材质统一；飘带、浪花、云霞等的位置、方向、体量和出现频率随内容变化。
4. 只改用户授权的页面和对象。用户已加好的动画、切换、触发关系与备注优先保护；默认备份并另存。
5. 每次收录同时保留方法、实际素材、可编辑案例与验证状态；缺少的部分明确写“待提供”。
6. **效果图忠实复刻**：用户确认的 PPT 效果图是视觉验收基线；输出 PPTX 必须完整还原其构图、配色、纹理、渐变、照片、图层、角标和小图标，不能因为可编辑实现不便就省略或以低质替代。标题、正文、数字等必须保持原生可编辑；复杂装饰允许作为独立高质量图像/矢量层保留，不与文字烘焙成整页截图。逐页对照验收，标明未还原项与非原生可编辑项。
7. 当前新要求优先于旧偏好；不要从“上次这样做”推断所有新项目也必须这样。

## 一、设计原则：统一而有呼吸感

### 1. 先安排信息，再安排装饰
先确定每页要让观众记住的一件事，再安排信息层级、图文关系和留白。内容多时先压缩文案、拆页或调整结构；不要不断缩小字号来迁就装饰。高级感来自比例、排版、材料与节奏，不能按装饰数量衡量。

采用“完整但克制”的构图：主体清楚，边缘有主次，局部留白有去向。空白若有对齐、视线或章节停顿作用就保留；若一侧存在强飘带、另一侧明显失衡，再用更轻的图标、远山、云霞或浪花呼应。

### 2. 统一什么，变化什么

| 保持统一 | 随内容变化 |
| --- | --- |
| 主色与辅助色的角色、饱和度区间 | 飘带的弯曲、方向、起止位置 |
| 字体层级、正文对比度、边距秩序 | 单图、双图、圆形、对照、时间轴等构图 |
| 金边的细度、纸张与水彩的材质语言 | 装饰体量、透明度、疏密、局部裁切 |
| 图标的线宽、圆角、视角和复杂度 | 云霞与浪花在少量页面的出现位置 |
| 照片图框、标题与内容的视觉关系 | 不同章节的主视觉重点与呼吸停顿 |

不要把“统一”理解成所有页面复制同一个角落；也不要为变化引入无关的新材质、新色系和新图标风格。

### 3. 色彩角色与照片融合
为当前主题定义：背景色、正文色、主题色、金属/强调色、低对比装饰色。色值是风格包的内容，不把海岛青色固化为通用规则。

优先用共同的浅底、线条和材质衔接照片。保留照片自然色，不为了模板将晚霞强行染成青色。让照片中少量粉紫、橘金呼应边角极淡的云霞；照片已经色彩丰富时，周围装饰要减量，文字仍用高对比正文色。不要同时在飘带、浪花、标题、阴影上放多种高饱和彩色渐变。

连续色彩过渡只在用户明确选择时使用；“翻页有变化”不自动意味着主题色逐页改变。海岛案例最新选择是全套青金，覆盖此前青到蓝的实验。

### 4. 点缀组件的职责
- 飘带：形成方向、框景和页面边缘的主势，绕开标题、人像和正文。
- 浪花：接住部分中间空页的下缘或侧缘；不要每页出现，也不要爬上图片说明。
- 云霞：少量页顶或边角的柔和色温与层次，位置可错落，避免标题背后出现强纹理。
- 远山：低对比的空间层次，与主体保持清楚距离。
- 海鸟、图标：形成小尺度焦点与题材线索，数量少、风格一致。
- 金线：解释结构或强调材料边缘。不得给每个文字块机械加横线。
- 纸张：承载历史或叙事内容；纹理在文字周围退让，三张同类纸也应有细微色温和旧痕差别。

装饰必须能说明其作用。无法说明时先删掉，再看构图是否更清楚。

### 5. 页面节奏与版式族
根据内容建立少量版式族：封面、章节页、同页对照、左右图文、照片叙事、信息结构/时间轴、诗词/结束页。避免把所有页面做成整页图片，也避免连续套用同一左右模板。

用缩略图总览检查：相邻页面是否同一个重角；是否有连续过满或过空；章节页是否像停顿；照片与正文页是否有节奏。可以先把页面标为“轻 / 中 / 强”，再检查排列，标签只用于制作记录，不出现在正式 PPT。

### 6. 排版与字体
为文字预留干净区域，统一对齐基线和段落间距；用字号、字重和位置表达层级。以实际投影/手机预览检查可读性；正文不使用过浅灰色。

保留用户已经认可的大标题、小标题样式。海岛案例的小字用微软雅黑；其他项目依据语言、设备与字体可用性决定。字体缺失时明确替代及其换行影响，不能只改字体名称就宣称显示一致。

将背景肌理、真实照片、文字和装饰分层；在页面边缘延展装饰时处理好裁切，不留下突兀断口。图框与细线要有一致尺度，不能用粗框包围所有内容。

### 7. 迁移到其他主题
| 场景 | 可选视觉语汇 | 约束 |
| --- | --- | --- |
| 海岛、旅行 | 海浪、远山、海鸟、青金飘带、淡云霞 | 保持主色，不每页堆海浪 |
| 古建筑、历史 | 檐角、窗棂、山石、古纸、印记 | 基于具体时代与建筑语境；不虚构文物来源 |
| 学术汇报 | 清晰网格、简洁图标、细线、轻几何纹理 | 图表与证据优先，装饰不能暗示错误数据 |
| 其他品牌主题 | 品牌形态、材料、色彩角色 | 重新选取语汇，不自动复用海岛边框 |

跨主题复用的是信息组织、层次、组件化和疏密判断；素材与色彩应重新适配。

### 8. 已确认效果图的忠实复刻（2026-11-09 新增·最高优先级）

**定义**：当用户要求先绘制/审定效果图，再制作最终 PPTX 时，效果图就是交付的视觉基准，不是“仅供灵感参考”。对每张页面分别建立《效果图→PPTX 对照单》；只有明确得到用户许可，才可调整版式或省略装饰。

**双目标并行，而非二选一**：
1. **视觉复刻**：主副标题的字形和层级、卡片宽高位置、栏距、页边距、圆角、细金边、照片、底纹、色彩、光影、渐变、透明度、图标及其尺寸、徽章、丝带、纹章、建筑与山峦剪影，均需逐项对齐效果图。尤其是警帽、天平、电影场记板、书本、盾牌、气泡、靶心、纸夹、人物剪影等微型组件，不得为了省时间而消失，不能使用风格不一致的 emoji 代替。
2. **文本可编辑**：标题、正文、引言、引号文字、数字、标注、表格文案必须采用原生文本框；尽量保留图表数据与重要流程关系的原生可编辑结构。不能把整个页面截图当成一张背景后叠几个透明文本框，伪称已完整可编辑。
3. **装饰保真**：复杂纹样、纸纹、真实照片、建筑/警员剪影、精致徽章与难以由少量 PowerPoint 形状重建的装饰，可以作为**独立高清位图、透明 PNG 或 SVG** 放入 PPTX。尽量按逻辑分层，保证独立移动、替换与重新排版；有源文件则同时保留，明确素材内部是否可拆改。
4. **先做资产盘点**：制作 PPTX 前逐页提取一份视觉组件清单：背景/纹理、每个图标、照片及蒙版、卡片、线条、装饰、文本与数据；对无法直接复用的元素，应先重绘/制作素材，而不是删掉它。
5. **固定尺寸比对**：每页导出与效果图相同的 16:9 画幅或同尺寸图，逐页目视对照布局、层次、色差、文本换行、图标是否存在、照片渐变遮罩和边缘裁切。必要时叠图定位误差；放大检查小图标、细线和文字。不能拿设计效果图代替 PPTX 的真实导出图进行验收。
6. **交付报告**：逐页列出已复刻组件、原生可编辑对象、独立矢量/图片对象及仍有差异；只在真实渲染和目标软件检查后标注通过。无法达到的要如实报告，不能宣称“完全复刻”。

**优先级解释**：新增规则并非要求让背景中每粒纸纹都成为原生形状，而是要求在正文文字和关键结构可编辑的前提下，保持效果图视觉完整。用户未确认的新 PPT 可以先探讨风格；用户已确认效果图的 PPTX 不可擅自二次简化。

**特别防回退项**：不得丢失警帽、天平、电影拍摄场记板、书本、盾牌等类别的小图标；不得漏掉右上角公安建筑的柔和渐隐照片；不得用纯色矩形替代图中具有层次的丝带/磨砂卡片；不得把下方渐变山峦或人物剪影“一键省略”。

## 二、可编辑与已有动画保护

### 1. 可编辑交付标准
默认交付原生 PPTX。不要将整页先生成图片再宣称自动转成完全可编辑。允许将复杂的纯装饰作为图片，但要明确范围。

| 对象 | 默认要求 | 不应混淆的能力 |
| --- | --- | --- |
| 标题、正文、诗文、数字、年份、图例 | 原生文本框，可改字、字体、位置 | 图片里有字不等于文字可编辑 |
| 数据图表 | 优先原生图表及可改数据；复杂定制图保留数据与可编辑绘制对象并说明边界 | 图表截图不等于可改数据 |
| 时间轴、关系线、节点、卡片结构 | 原生形状/曲线/连接线，可独立选取 | 整张示意图只能整体移动 |
| 照片、人像、装饰纸纹 | 独立图片，保留比例、裁切和必要蒙版；纸上文案独立 | 图片内容本身不是原生形状 |
| 图标 | 优先适配目标软件的矢量/原生形状；记录格式 | SVG 可缩放不代表在 WPS 可拆分改色 |
| 纯背景装饰 | 可合并，保留来源/制作参数和可拆源文件（若有） | 合成底图内部不可分别移动 |
| 动画主体、阴影、遮挡层 | 分别独立对象，记录层级、身份与源素材 | 主体烘焙在背景里无法独立平滑 |
| 视频/音频 | 独立媒体，注明嵌入或外链，保留播放设置 | 截帧不等于视频已嵌入 |

复杂手绘绳索可用可编辑曲线加局部纹理，或独立纹理图；如采用纹理图，说明只能调整位置大小，不能声称每根纤维可编辑。素材中的文字须尽量重新以原生文本表达。

### 2. 修改已有动画稿：最小改动
1. 找到用户指定的真实文件；无法访问 Windows 路径时直说访问限制，不使用旧云端稿冒充本机动画稿。
2. 备份原件，记录文件哈希、页数和修改范围，另存输出。确认 WPS/PowerPoint 及版本是否已知。
3. 检查目标页、目标对象及其标识、关系、分组、裁切、形状、层级。页码与页面标题一起定位，避免插页导致改错。
4. 只更新授权文案、图片引用、裁切或必要属性。优先原位修改，不先删除对象再插入新对象。
5. 检查媒体是否被多处引用。局部换图时新增独立媒体关系，避免直接覆盖共享媒体影响其他页面。
6. 尽量保持对象 ID、名称、分组、顺序、动画目标、路径、触发器、切换、扩展数据、音视频依赖和用户备注。对象名一致只是辅助，不足以证明平滑匹配。
7. 不用可能丢失扩展信息的工具重新保存整份文件。对于窄范围替换，优先经过检查的包级补丁；保留未知命名空间及扩展。XML 前缀或序列化变化也要检查兼容性，无法证明安全时交付副本并说明验证范围。
8. 比较包结构、未涉及部件和动画相关结构，逐页渲染受影响页面；在目标软件中播放被改页及相邻切换。
9. 未做真实播放时明确标为“结构检查通过；播放待验证”。不得从 XML 相同推断用户看到的动画必然相同。

### 3. 可以改变和需要保护的边界
换图允许目标图片、关系引用和裁切发生必要变化；改文案允许对应文本节点变化。除此之外的变化都必须能解释。保护动画不意味着目标页面 XML 完全不能改变，而是修改范围应受控、依赖和身份应保持。

当换图的比例影响原效果，优先通过裁切维持对象边界；需要调整对象本身的大小、路径、组结构时，先说明这与既有动画的耦合，再按用户范围实施。不要为了“好看”擅自重排整页。

### 4. 图片与文字质量
先看原图，确认水印、手机状态栏、播放控件、通知与实际画面范围。用户要求避开水印时，通过构图裁切排除，保留原图作源文件，不生成虚构的无水印来源。

圆形图片：保留原圆的位置、尺寸、轮廓和金边，调整图片内部裁切；检查海平线和主体位置，避免把图片拉伸。原图不足以实现构图时先呈现可用裁切，不偷偷补造真实景物。

清除制作过程的批注、教学框和临时占位文字。用户自己的演讲者备注默认保留；历史稿曾清空备注不构成以后删除本机备注的授权。

### 5. 可用的结构检查
运行 `python scripts/audit_pptx.py 原稿.pptx --compare 修改稿.pptx`。脚本只读，报告 ZIP 部件变化、原生文字/图片数量、对象身份、timing/transition/extLst 的规范化比较。
- 未变化：仅表示脚本覆盖的结构相同。
- 存在差异：结合具体修改范围审查，不将所有差异视为失败。
- 对象 ID 相同：不证明匹配行为正确。
- 静态渲染正常：不证明点击顺序、触发器、音视频和平滑切换正常。

## 三、平滑切换与动画准备

### 1. 能力与验收边界
接收参考视频、原 PPTX、素材与目标软件信息，分析画面如何从前一状态到后一状态。准备可编辑静态页、主体抠图、阴影、暗部虚化、遮挡层与前后状态，供用户最后设置“平滑”或相应切换。

用户已经设置好的动画优先保护。动画制作并非一概不能做；依据当前工具与目标软件决定是否可以写入，不能把“准备完成”说成“播放验证完成”。新写的动画也必须在实际目标软件验证。

### 2. 分析参考
记录：
- 参考来源、片段时间码、页面比例、已知软件和版本。
- 运动主体、静止背景、前后景、遮挡物、阴影、文字变化。
- 开始/结束位置、大小、旋转、裁切、透明度、运动方向和先后顺序。
- 是否存在模糊、蒙版、淡化、连续页接力或其他效果；无法由视频确定的部分标为推测。
- 哪些需要烘焙成图片，哪些应保持原生对象。

不能凭视频就认定它必然由某个菜单选项实现。需要精确 WPS 按钮位置时，用对应版本真实截图或官方说明核实；不要伪造软件截图。

### 3. 对象与状态规范
使用稳定语义名，例如 hero-nalong、hero-shadow、background-sea、foreground-frame。保留原文件已有名称；不要为了符合命名法重命名用户的动画对象。

跨页记录使用自定义 logical_id，帮助维护者跟踪同一视觉主体；它只是台账，不是 PowerPoint/WPS 的匹配指令。记录每页实际 shape_id、对象名称、分组路径和媒体关系。不要擅自把某一软件的特殊名称规则套用于所有版本。

每个状态记录 x/y/w/h、单位、角度、裁切、透明度、层级和可见性；统一单位。记录阴影是随主体运动还是固定，遮挡边缘是否需要补全。为移动后露出的区域补好背景，避免原主体残影。

### 4. 复制整页与复制主体
复制整页通常更容易保留相同对象和上下文，再移除或修改不需要的内容；仍需检查会不会保留多余对象或触发关系。只复制主体也可能可行，适合前后页内容完全不同，但不能只凭“同一张 PNG”就保证软件会正确匹配。

选择取决于目标软件、现有结构、主体关系与测试结果；不要规定所有平滑都必须复制整页。保留主体身份与正确的前后状态，比机械选择复制方法更重要。

### 5. 图片准备
保留未裁切原图与无损源文件；主体抠图输出透明 PNG，避免白底伪透明和边缘毛刺。分开保存主体、柔和阴影、背景、前景遮挡与必要模糊层。按实际显示比例准备足够分辨率，避免反复 JPEG 保存。

照片或截图存在水印/控件时先规划裁切；需要补绘时标记处理范围。模拟真实地点或人物不能把生成补绘误说成原始实拍。设计纹理可以生成，但记录来源与提示词。

### 6. 交给用户最后设置切换时
交付前后状态页、层级/对象映射与简短应用步骤。包含：需要添加切换的目标页、建议测试的顺序、参考时长（明确是否来自实测）、应看到的起止状态。不要在正式幻灯片画面内放这些操作说明；放在伴随记录中。

播放检查覆盖：从前一页进入、退回再进、连续播放、手动点击、阴影和主体同步、遮挡边缘、文字清晰度、音视频及原有触发动作。对未播放项明确标为待验证。

### 7. 两个待收录实例
在目录中预留 MORPH-001、MORPH-002，两者当前均为“待用户另一会话提交”。不预设实例内容，不伪造完成截图，不把待提交标为已验证。其他会话按收录模板补入后再合并目录和规范。

## 六、验收与交付

### 内容与视觉
- 文案、诗词、年份和事实有来源；个人经历不编造。
- 逐页渲染，检查裁切、遮挡、行距、段落、字体替换、金边、装饰断口和文字对比度。
- 用整套缩略图检查布局节奏、色调、边饰重复和疏密。不能只看封面就宣称全套通过。
- 图片不拉伸，水印/控件按授权裁切；边饰和纸纹不压文字。
- 正式画面不出现制作说明、批注框、临时占位和验收记录。

### 效果图复刻（新增）
- 对每页参考图与从最终 PPTX 实际导出的同尺寸图片进行一一比对，检查版式、色块、文字层级、渐变、质感、照片及蒙版、细线和边角装饰。
- 对照清单逐项核查所有小组件：图标、警帽、天平、场记板、书本、盾牌、靶心、对话气泡、引号、人物和建筑剪影。不可用 emoji、占位框或“简化图形”悄悄替换。
- 特别检查局部照片的渐隐遮罩（尤其右上公安建筑照片），下方纸质山峦/地标、透明 Venn 图/卡片层次、标题丝带渐变及装饰。
- 对不能复刻的部分给出具体差异，未经验证不得声称“完全一致”。

### 可编辑
- 抽查并必要时逐类检查：标题正文是文本；照片可替换；关键结构有原生对象；数据图表可改数据或限制已说明。
- 时间轴年份、卡片文案、悬挂结构没有被合成在一个不可拆图片里。
- 将动效所需主体、阴影、遮挡和前后景拆开；列出允许合成的背景层。
- 文件未从整页图片“伪装”成可编辑 PPT。

### 已有稿保护
- 原稿有备份；修改范围、输出文件可追溯。
- 比较页数、页面顺序、未改页、对象身份、timing/transition、扩展和媒体依赖。
- 非预期变化已解释或修复；共享媒体替换未波及其他页面。
- 用户备注与原有对象没有被未经授权删除。
- 将结构比较与真实播放结果分别记录。

### 目标软件
- 在 WPS/PowerPoint 对应版本检查字体、行距、裁切、透明度、矢量及曲线。
- 播放受影响页与相邻页：检查切换、触发器、路径、音视频和遮挡。
